Что исправлено:

- исправлены URL статических страниц и добавлена генерация `/about/`, `/contacts/`, `/privacy/` при наличии исходных HTML;
- убраны мёртвые `#`-ссылки из футера и боковой панели;
- добавлена безопасная работа с `localStorage` для избранного и кеша;
- исправлены HTML-атрибуты для пользовательских/JSON-данных через `escapeAttr`;
- добавлены canonical URL и Twitter meta;
- добавлена генерация HTML для главной и категорий до запуска JavaScript;
- добавлена валидация данных и безопасные требования к ID/дате/readTime новых статей;
- категориями управляет единый `utils.js`, а не несколько копий mapping;
- обновлён Service Worker cache version;
- `npm start` теперь собирает проект и отдаёт готовый `dist`;
- build генерирует RSS и sitemap;
- фиктивный идентификатор Yandex.Metrika удалён из генератора.

## Как работать с сайтом (workflow)

Сайт: https://xaosland.ru · Репозиторий: github.com/xaosland/xaosland-improved

Источник истины — **этот репозиторий**. VPS (`/var/www/xaosland-git`) — клон репозитория,
который собирает сайт и атомарно выкатывает его в `/var/www/xaosland/dist`.
Старую папку `/var/www/xaosland` на сервере руками не редактировать.

### Обычный цикл правок (PhpStorm)

```bash
git pull origin main        # 0. подтянуть изменения (cron авто-коммитит новости!)
# ... правки в PhpStorm ...
git add -A && git commit -m "описание правки"
git push origin main        # 1. отправить в GitHub
npm run deploy              # 2. собрать на VPS и выкатить (см. ниже)
```

`npm run deploy` — это SSH на VPS и запуск `scripts/deploy.sh`, который:
`git pull → npm run build → проверка целостности → бэкап старого dist → атомарная подмена`.
Работает из любого терминала, где есть SSH-ключ (Windows/WSL).

### Типовые задачи

- **Правка кода/стилей** — обычный цикл выше.
- **Новая статья руками:** `npm run add:article -- путь/к/статье.md` (в файле — frontmatter:
  id, category, title, excerpt, date, readTime; примеры в `data/content/*/`),
  затем commit → push → deploy.
- **Правка существующей статьи:** файл в `data/content/<категория>/<id>.md`,
  метаданные — в `data/base.json`. После правки обязателен `npm run build` локально
  для проверки (или сразу push + deploy).
- **Новости:** пишутся автоматически cron-ом на VPS каждые 2 часа
  (см. ниже). Вручную добавлять не нужно — будет конфликт с авто-коммитами.

### Перед PR

```bash
npm run validate && npm run build   # валидация + локальная сборка dist/ (не коммитится)
```

## Автоновости (RSS-парсер)

`scripts/fetch-news.js` тянет новости из RSS-лент (Habr, OpenNET, Lenta.ru, 3DNews, IXBT),
скачивает текст каждой статьи (до ~10 предложений, `NEWS_SENTENCES`), отрезает комментарии
и складывает их в категорию **Новости** (`/news/`).

Запускается cron-ом на VPS каждые 2 часа: pull → парсинг → авто-коммит `data/` → push → деплой.
Логи: `/var/log/xaosland-news.log`. Состояние дедупликации: `data/news-state.json` (не редактировать руками).

Переменные окружения: `NEWS_MAX_HOURS` (максимальный возраст новости, по умолчанию 26),
`NEWS_MAX_PER_RUN` (лимит статей за запуск, по умолчанию 12), `NEWS_SENTENCES` (предложений в статье, по умолчанию 10).

Локальный запуск `npm run fetch-news` возможен только для отладки: у локальной копии
своё состояние дедупликации, и новости могут задублироваться с VPS. Не пуши локальные
изменения `data/` от парсера.

## Важное ограничение исходного набора

В переданных исходниках отсутствуют `data/content/**.md`, а также `about.html`, `contacts.html`, `privacy.html`. Поэтому сборка создаёт статьи с предупреждением об отсутствии Markdown-контента, а статические страницы будут сгенерированы автоматически после добавления соответствующих исходных файлов.

Установка зависимостей:

```bash
npm install
```

Сборка:

```bash
npm run build
```

Локальный запуск:

```bash
npm start
```
